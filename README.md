# Edge-Computing Reference Architecture for Real-Time Structural Health Monitoring

Reference implementation and public-data validation for the paper

> P. Yan, *An Edge-Computing Reference Architecture for Real-Time Structural Health Monitoring: Design and Validation on Three In-Service Bridges*, 2026. Preprint identifier pending. Software DOI pending Zenodo archival.

The architecture moves anomaly detection to an edge node at the structure (4 GB memory, general-purpose CPU, no accelerator), transmits compact health summaries and anomaly events rather than raw waveforms, and keeps assessing the structure when the network is down. This repository contains everything needed to regenerate every number in the paper from openly licensed monitoring data recorded on three in-service bridges.

Documentation: `docs/index.html` (also served at the project site).

## What is validated

| Structure | Form | Data | Reference condition | Changed condition |
|---|---|---|---|---|
| KW51, Leuven, Belgium | Steel bowstring railway bridge | Maes & Lombaert, Zenodo [10.5281/zenodo.3745914](https://doi.org/10.5281/zenodo.3745914), CC BY-NC-SA 4.0 | Jan 2020, after retrofit of the diagonal connections | Jan 2019, before the retrofit |
| Vänersborg, Sweden | Riveted steel bascule railway bridge | Leander et al., Zenodo [10.5281/zenodo.8300495](https://doi.org/10.5281/zenodo.8300495), CC BY 4.0 | Openings before 9 Mar 2023 | Openings after a verified fracture |
| Chillon, Switzerland | Prestressed concrete box-girder viaduct | Martín-Sanz et al., Zenodo [10.5281/zenodo.3234805](https://doi.org/10.5281/zenodo.3234805), CC BY 4.0 | Normal operation, 26 Mar to 8 Jun 2017, 7 to 26 °C | none (false-alarm rate across the temperature range) |

Results of the deployed detector (PCA on the spectrogram, fitted per structure on reference-condition windows only), from `results/summary.json`:

| | KW51 | Vänersborg | Chillon |
|---|---|---|---|
| AUC | 0.925 | 0.620 | n/a (reference only) |
| Sensitivity at threshold | 35.4 % | 2.2 % | n/a |
| Specificity at threshold | 98.89 % | 95.69 % | 99.44 % |

Edge latency, raw window to decision, batch size one, inside a 4-vCPU / 4 GB container: 59.0 ms mean, 98.9 ms P95, 375 MB peak resident memory (`results/latency_pca_info.json`). A 34.3 M-parameter masked-autoencoding Vision Transformer evaluated under the same protocol reaches AUC 0.905 on KW51 and 284 ms mean latency; it is reported in full as the learned alternative (`results/rescore/summary.json`).

The Vänersborg result is a scoped negative finding: a generic spectrogram detector on the available channels does not separate pre- and post-fracture openings. It is kept in the paper and here because the protocol is the same for all three structures.

## Layout

```
shm/                 the pipeline
  datasets.py        loaders for the three public datasets; builds cache/v2/<S>.npz
  frontend.py        per-structure front ends (window length, FFT geometry, channel subset, level removal)
  spectrogram.py     100 x 200 log-PSD images
  evaluate.py        PCA detector (deployed), threshold calibration, per-window export
  train.py           MAE-ViT per structure (learned alternative)
  rescore.py         masked-patch and latent scores for the saved ViT weights
  merge_rescore.py   folds ViT scores into the export
  raw_sample.py      raw test windows for the latency probe
  latency_pca.py     edge-latency probe, PCA detector (run inside the container)
  latency.py         edge-latency probe, ViT
  diagnose*.py       the diagnostics that led from the v1 front end to v2
docker/Dockerfile    the 4-vCPU / 4 GB edge-node emulation image (python:3.7-slim, CPU torch)
data/chillon_list.txt  Chillon file manifest with Zenodo URLs and md5 checksums
results/             the per-window exports, ROC and threshold sweeps, latency samples, summary.json
                     exactly as read by the paper's build script
download.sh, download_chillon.sh, run_v2.sh, run_pca_latency.sh, finish_v2.sh
```

Raw data (about 5 GB) and trained weights are not in the repository; both are regenerated by the scripts below.

## Reproduce

Host requirements: Python 3.7 or later, `pip install -r requirements.txt`, Docker for the latency measurement.

```
./download.sh && ./download_chillon.sh        # ~5 GB from Zenodo, resumable
docker build -t shm-edge:py37 docker/
./run_v2.sh                                   # caches, PCA + ViT per structure, evaluate, ViT latency
python3 -m shm.rescore --k-masks 4            # masked ViT scores (no retraining)
python3 -m shm.merge_rescore
./run_pca_latency.sh                          # PCA fit + container latency
```

Outputs land in `out/` with the same file names as `results/`. The three ViT trainers run in parallel and take several hours on a multi-core CPU; the PCA detector alone takes minutes.

## Protocol in one paragraph

Per structure: 60 s windows, one per channel. KW51 and Chillon are resampled to 100 Hz, 20 s Hanning frames stepped 0.4 s, 2000-point FFT, 0.05 Hz bins over 0 to 9.95 Hz; Vänersborg stays at 200 Hz with 2 s frames and 0.5 Hz bins over 0 to 99.5 Hz. Each window is a 100 x 200 log-PSD image, mean-removed and min-max scaled with training-set extremes. Reference-condition files are split 60 / 20 / 20 into train / calibration / test by source file (seed 0); changed-condition files are test only. The detector is PCA retaining 95 % of variance; the score is the mean squared residual; the threshold is median + 2.5 sd of the calibration-split score. Full detail is in the paper, Sections 4 and 5.
